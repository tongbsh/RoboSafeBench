## TaskContext 估计的假设及其在真实基准上的失效情形

数值都来自 `probe.yaml`，没有代码默认值。

1. **名义路径 = 逐阶段归一化时间上的逐坐标中位数**：各次运行在每个阶段内线性插值到等分的归一化时间，取逐坐标中位，再放到中位阶段边界时刻上。
   - 失效：多模态演示（绕左 / 绕右）的中位数可能是一条谁也不走的路径，`p*` 可能落在障碍里。
   - 失效：逐坐标中位不保证路径光滑或满足运动学。
   - 失效：阶段内速度剖面差异大时，等分归一化时间会把“停顿”抹平。
2. **阶段由夹爪事件切分，事件签名取众数**：签名不同的运行被丢弃并计数。
   - 失效：二次抓取、抓取失败重抓、两指非对称夹爪会产生不同签名，丢弃过多会触发 `min_consistent_runs`。
   - 失效：无夹爪任务（推、按按钮）只有一个 `approach` 阶段。
   - 失效：多子任务序列（LIBERO-Long、CALVIN 链）需要按子任务切分，本实现没有。
3. **夹爪开度按每次运行的最大绝对值归一化，带滞回阈值**：假设开度单调对应开合，且每次运行都完整张开过一次。
   - 失效：开度信号是命令而不是测量；夹爪一直半闭。
   - 失效：开度为负号约定的基准。归一化只除以最大绝对值，不翻转符号，负值会一直低于闭合阈值，被当成全程闭合。接入时需要在宿主侧把开度转成“张开为正”。
4. **事件时刻的分辨率是一个 trace 采样（一个控制步）**：开发中实测，时间缩放 0.8 的运行，闭合事件落在 0.75 s 和 0.76 s 两个采样之间，被量化到 0.76 s。
   - 失效：控制频率低的基准（ManiSkill2 5 Hz = 0.2 s）上，阶段边界误差可达 0.2 s，`anchor_phase.frac` 对应的命中时刻随之偏移。
5. **姿态**：每步都有四元数时取符号对齐后的归一化均值，否则用单位四元数并记录。
   - 失效：EEF 绕工具轴大幅转动时，均值不代表任何实际姿态。目前实例化只用位置，姿态只记录。
6. **工作区**：有声明时用声明的盒子，否则用所用运行中 EEF、机器人碰撞体、物体位置的包围盒（`probe_hull`）。
   - 失效：包围盒只覆盖探针走过的区域，`fall` 的释放点（在 EEF 上方）几乎总会超出，导致大量 `release_height_out_of_workspace`。真实基准应在 BD 或注解里声明工作区。
7. **支撑面**：优先用宿主 `support_surfaces`；否则在“最低任务物体中心 − `surface_below_object_m`”处估一块水平面，范围为物体与 EEF 的 xy 包围盒。
   - 失效：多层架子、倾斜面、抽屉内部；物体初始放在小托盘上时，估计面偏高、范围偏小。
8. **实体顺序（R3）**：静态声明 → 被抓物体（`held_object` 出现的运行比例 ≥ `entity_min_run_fraction`）→ 被移动物体（位移 > 阈值）→ 注解。
   - 失效：被推动的干扰物会被误当作任务实体。
   - 失效：宿主不报告 `held_object` 时，被抓物体只能作为“被移动物体”进入。
9. **首次接触检查默认只看 EEF**：trace 里每步都报告同一组机器人碰撞体时，才对这些碰撞体的中位路径做 `early_contact` 检查；否则记 `early_contact_check: eef_only`。
   - 失效：`fall` 落向夹爪时，腕部或前臂（在 EEF 上方）可能先被砸到，而 G0 看不到。测试 `test_early_contact_uses_robot_bodies_when_the_probe_has_them` 展示了这种差异。
   - H 类任务的 trace 录制应报告机器人连杆位置。
10. **名义速度 = 速度 > `moving_speed_min_mps` 的 EEF 采样的速度中位数**（T_stop 协议用）。
    - 失效：速度剖面很不均匀（快速逼近、慢速对准）时，中位数不代表 `p*` 附近的速度。
11. **探针运行必须成功且无危险**：有 `in_contact` 或危险体处于 kinematic / released 的运行被丢弃。
    - 失效：基准的成功判定有噪声时，有效运行数可能不足。
12. **一个宿主同时只能有一个 `EpisodeSession`**：`HazardRuntime` 在构造时调用 `host.install_hooks`，后建的会话接管钩子，先建的会话再用就会触发 `begin_episode without arm()`（开发中遇到过）。
    - 失效：在同一宿主上并行做探针录制和门控。

## 强度 → 原语参数的映射（`hazardlib/instantiate/mapping.py`）

命中点 = `p_ref + standoff·n̂`，其中：
- `p_ref` = 名义 EEF(`t_hit`) + `exposure.offset_m`，即 `provenance.anchor_point`；
- `standoff = r_hazard(n̂) + eef_contact_radius_m`；
- `t_hit` = `anchor_phase` 的起点 + `frac` × 时长。

强度向量到原语参数：

- **`intrusion.fall`**（轴 `tau_s`，可选 `mass_kg`）：释放高度（相对质心命中点）\(h = g\tau^2/2\)，`g` 取 BD 的 `gravity_mps2`。静止释放，`release = onset = t_hit − τ`（D2）。
  - 例：τ = 0.4 s → 0.78 m，0.5 s → 1.23 m，1.0 s → 4.9 m（`test_fall_release_height_uses_bd_gravity`）。
  - `mass_kg` 若给出，必须等于 `agent.mass_kg`。
- **`intrusion.slide`**（轴 `tau_s`、`approach_speed_mps`）：在支撑面上匀速 \(v\)，起点距命中点 \(v\tau\)（测试中 0.5 m/s × 0.3 s = 0.15 m）；质心高 = 面顶 + z 半尺寸；释放速度取固定窗口差分（D4）。
- **`intrusion.reach`**（轴 `tau_s`、`approach_speed_mps`，可选 `limb_size_m`）：`approach_speed_mps` 是命中时刻的末端速度 \(v\)。
  - 记 \(\kappa\) = `intensity.yaml: mapping.intrusion.reach.overshoot_fraction` = `overshoot_m / reach_distance_m`。
  - 命中时末端走完全程 \(L\) 的比例 \(f = 1/(1+\kappa)\)，对应速度剖面 \(s\) 的归一化时间 \(u = s^{-1}(f)\)。
  - 全程时长 \(T = \tau/u\)，命中速度 \(= s'(u)\,L/T\)。由此 \(L = v\tau/(u\,s'(u))\)，`reach_distance_m` \(= fL\)，`overshoot_m` \(= \kappa f L\)。
  - `linear` 剖面下 `reach_distance_m` \(= v\tau\)，`overshoot_m` \(= \kappa v\tau\)（`test_reach_mapping_linear_profile`）。
  - \(\kappa \le 0\) 时末端在命中点停下（min_jerk 下速度为 0），属于准静态占用，拒绝，原因 `reach_zero_overshoot`（D6）。
  - `limb_size_m` 只记录。

需要的常数只有 \(\kappa\)，在 `intensity.yaml` 里为 `PLACEHOLDER`；测试夹具取 0.25。

## 各基准 `fall` 族的可行 τ 区间

G0 的规则是释放点 z ≤ 工作区上界 + `g0.workspace_margin_m`，所以
\[
\tau_{max} = \sqrt{2\,(z_{top} + margin - z_{hit})/g},\qquad z_{hit} = z_{EEF}(t_{hit}) + standoff .
\]
另有 `onset_margin_s ≥ 0`，要求 τ ≤ `t_hit`。τ 的下限不由 G0 决定，取 `intensity.yaml` 注册区间的下界；要得到 `wait_solvable`，实际上还需要 τ > T_stop。

- **FakeHost（测试世界）**：
  - 工作区上界 1.0 m，margin 0.05 m，g = 9.81 m/s²，standoff 0.06 m。
  - 在 0.05–0.6 s 上以 0.01 s 步长逐个跑 G0，可通过的 τ 与闭式一致：
    ```
    pick approach frac=0.75: z_hit=0.360 t_hit=0.450 top=1.050  tau_max(closed)=0.3751  min(t_hit, tau_max)=0.3751  G0-pass grid: [0.05, 0.37] (33 values)
    pick carry frac=0.50: z_hit=0.360 t_hit=0.900 top=1.050  tau_max(closed)=0.3751  min(t_hit, tau_max)=0.3751  G0-pass grid: [0.05, 0.37] (33 values)
    low approach frac=0.75: z_hit=0.110 t_hit=0.750 top=1.050  tau_max(closed)=0.4378  min(t_hit, tau_max)=0.4378  G0-pass grid: [0.05, 0.43] (39 values)
    ```
  - 即 pick 任务（EEF 高 0.3 m）τ ≤ 0.375 s，low 任务（EEF 高 0.05 m）τ ≤ 0.438 s。端到端里 τ 0.5 s 的 `fall_high` 因此被拒。
- **CALVIN、LIBERO、RoboTwin、ManiSkill2 等真实基准**：无数据。`02_benchmark_profiles.md` 没有数值化的工作区上界或桌面高度。唯一相关的一处是 LIBERO 行的“台面高度需从固定装置读取 **[待探针]**”（第 76 行）。按上式，工作区上界比命中点高 Δz 时，τ_max = \(\sqrt{2\Delta z/9.81}\)：Δz = 0.5 m → 0.32 s，1.0 m → 0.45 s，1.5 m → 0.55 s。要让 τ ≥ 0.5 s，需要释放点比命中点高 ≥ 1.23 m，桌面场景通常做不到。这说明 prompt 里列为 [开放] 的“前导运动”可能是扩大 `fall` τ 的唯一办法。

## 偏离设计文档之处与理由

1. **G1 与校准函数接收 `EpisodeSession` 而不是 `host`**。实际签名：
   - `run_g1(session, instance, policy, tc, settings, seed, env)`；
   - `run_t_stop_protocol(session, policy, tc, settings, seed, env)`。

   理由：`HazardRuntime` 构造时安装钩子，同一宿主上的第二个运行时会接管钩子（见“假设”第 12 条），所以会话必须由调用方持有并复用。TC 用来定回合长度和名义速度，settings 提供所有数值（无默认值）。
2. **`instantiate(spec, tc, seed, bd, settings)` 多一个 `settings` 参数**：关键帧间隔、插值容差、释放窗口、\(\kappa\) 都来自 YAML。显式传入后，函数仍是纯函数，测试也能传测试夹具的值。
3. **CLI 多了 `record` 与 `verify` 两个子命令**：`record` 生成探针 trace（`probe` 的输入，同时导出 BD），`verify` 校验冻结结果。宿主和策略用 `--host/--policy 模块:工厂` 加载，因为本任务不能写真实宿主。
4. **暴露判定的 `p*` = `provenance.anchor_point`（名义 EEF 上的点加 `offset_m`），不是质心命中点**：00 §5.2 的 `p*` 定义在名义 EEF 路径上；质心命中点在其 standoff（≥ 危险体半径）之外，用它会把贴近的机器人也算成远离。
5. **T_stop 协议的触发方式**：00 §7 只说“在名义逼近速度下发出保持动作”。本实现在 EEF 速度首次 ≥ `trigger_speed_fraction` × 名义速度的控制步发出 `hold_action`，记录 `record_s` 秒，到时仍未停下的算删失。
   - 两个数放在新的 `intensity.yaml: t_stop_protocol` 小节，因为 D3 的 `calibration` 小节已被 `test_intensity_config` 固定了键集合。

### 偏离与理由

1. **新增 `HazardRuntime.hazard_handle(env)`**。prompt 只要求 `hazard_state`，但删除 `_HostTap` 后，可见性测量（`render_check(handle, ...)`）仍需要句柄。它同样是特权接口，docstring 指向 `hazard_state` 的约束。
2. **回退值检查扩展到各检查的 `measured`**。`probe_calibration` 的来源只出现在 C10 的 `measured.t_stop_settings` 里，`runtime_config` 只覆盖 `probe_runtime`；只查 `runtime_config` 会漏掉“T_stop 设定来自回退值”。实现是按 `{value, source}` 结构递归扫描所有检查，不写死 C10 的键（T05-F 会改 C5/C8 的键）。
3. **检查 `runtime_config` 是否完整**。缺字段或缺 `source` 都算问题，否则删掉一项回退值就能绕过检查。
4. **`freeze` 接收报告与校准的路径，而不是已解析的字典**。这样报告一定经过 `read_report` 的格式校验（T05 公开接口），校准一定经过 `read_calibration_summary` 的一致性检查，CLI 与库也走同一入口。
5. **校验校准文件格式**。`read_calibration` 拒绝不是 `hazardctl calibrate` 写出的文件（例如缺 `t_stop`），避免把任意 YAML 的哈希写进 Manifest。
6. **共享的 session fixture 放在 `pipeline_world.py`，不在 `tests/pipeline/conftest.py`**。在 pytest 的 prepend 导入模式下，第二个 `conftest.py` 会顶替 `sys.modules["conftest"]`，`test_spec_objects.py` 的 `import conftest` 随之失败。测试模块改为显式 import 这些 fixture。
7. **第 1 项和第 2 项的接线合在一个提交（8f9ebcb）**。Manifest 字段改为必填后，freeze 必须同时给出两个哈希，否则中间提交的测试不绿。
8. **修了 T06 自己的 `test_importing_the_pipeline_loads_no_simulator`**。它检查本进程的 `sys.modules`，而 `test_source_hygiene.py` 会导入 `hazardhosts.<bench>`，两者按这个顺序跑时会假失败。全量运行按目录顺序不会触发，所以此前没暴露；这次把两个卫生文件放在一条命令里跑时发现。现在改为在子进程里导入 `hazardlib.cli`，断言不变。另外手动确认过：在子进程里额外 `import hazardhosts`，集合中会出现 `hazardhosts`。
9. **测试数比 prompt 的参照多 13**，原因见验收第 1 条。

### 未解决与建议

- **建议**：`calibration.yaml` 自带 `bd_hash` 与 `task_context_hash`，freeze 可以再检查它们是否等于冻结 BD 和所给的 TaskContext。这超出 D13 b，本节没有做。
- **与 T05-F 的衔接**：本实现只依赖报告的这些部分：`verdict`、`bd_hash`、`adapter_version`、`config_hashes`、`runtime_config`、`checks[].measured` 中的 `{value, source}` 结构，以及回退来源的前缀 `conformance.yaml:`。T05-F 会改 `config_source` 的写法与 C5/C8 的键，这些不影响本实现。如果它改了回退来源的前缀，`FALLBACK_SOURCE_PREFIX` 需要同步。合并时请对照这一点，以及 `read_report` 新增的校验。
