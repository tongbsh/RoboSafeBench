## 对设计文档的修订建议（只提议，不改文件）

下面是 §6 与 D9 里我认为有歧义或可能不自洽的地方，按“对结果影响的大小”排序。前三条会直接影响 T04 的实现，建议在放行 T04 前定下。

1. **“官方接触”是否包含与 `scene` 的接触，§6 与 R8 的措辞不一致。** R8 对 fall 族写“其全部接触都是官方接触（与场景物体的接触按伙伴类别 `scene` 记录）”，但 `first_official_contact_t_s`、`partner_class`、`v_rel_normal_mps`、`impulse_analytic_ns` 显然是“危险体撞到机器人”的量。我按“官方接触 = 与机器人侧伙伴的接触”实现了时长与 `clamp`，`scene` 接触可以是官方**事件**但不计入接触时长与机器人接触。建议明确：哪些量以机器人侧接触为准，`scene` 接触是否单独记一个事件类别，并改写 R8 的那句括号。
2. **`hazard_induced_unstable` 的归因窗口没有结束时间。** D9 d 只有“时刻 ≥ onset 且距离 ≤ 阈值”。一个在 onset 后几十秒、危险体早已落定之后才出现的不稳定，只要实体靠近危险体质心就会被归给危险体，而且这一类**留在分母里**，会稀释指标。任务文件也问了这一点。建议增加 `stability.attribution_window_s`（YAML 预注册），或要求不稳定发生时危险体仍处于运动 / 接触状态。同时请说明：当“不稳定实体”本身就是危险体（距离 0）时是否一律归为危险体引起。
3. **接触速度取质心速度还是接触点速度。** D9 a 的 `v_n = max(0, (v_partner − v_hazard)·n)` 只说了速度，没说是哪一点的。对旋转的危险体或机器人连杆，接触点速度与质心速度可以差很多。`RobotState.collision_body_lin_vel_mps`（T01）给的是碰撞体位置处的线速度，T04 需要知道危险体速度是质心还是接触点；建议规定统一用**接触点处**的速度。
4. **BD 里 `robot_contact_bodies` 的模式语义。** 01 §2 的示例是 `include: [arm, gripper, held_object]`。子串匹配下 `arm` 会匹配 `armchair`、`alarm_clock`、`farm_table`，把场景物体误判成机器人。建议 BD 明确匹配方式（精确名、前缀或子串，可逐项声明），或示例改用带前缀的写法（如 `robot0_`）。我的实现已按子串匹配并在文档字符串写明。
5. **`held_object` 只按名字精确匹配。** 一个物体可能有多个几何体 / 连杆，适配器报告的碰撞体名未必等于 `RobotState.held_object`。建议 `RobotState` 或 BD 提供“抓持物的碰撞体名列表”，而不是单个名字。
6. **`J = m(1+e)vₙ` 隐含“机器人质量远大于危险体”。** 旧实现的注释写明“μ≈m_hand（arm ≫ palm）”。对轻量机器人或重危险体，有效质量应是折合质量。§6 没有说明这个假设，建议写进语义定义，并在报告里注明。
7. **`clamp` 的“静态场景体”无法区分。** §6 说“一个静态场景体（或机器人另一部件）”，但伙伴类别里 `scene` 也包括未抓持的、可移动的任务物体，所以危险体被压在机器人与一个可移动物体之间也会判 `clamp`。如要区分，`ContactObs` 需要一个“静态”标记。
8. **`toppled` 没说是谁倾倒。** 是危险体、被操作的任务物体，还是场景里任意物体？旧后端各不相同。`tilt_deg_up_axis` 与 `is_toppled` 与对象无关，但事件记录里的 `toppled` 需要指明；参考姿态（哪个时刻）也没说。
9. **“接触前剩余时间序列”（§6）与 `ttc_min_s`。** 字面是“到首次接触还剩多久”，只在发生接触时才有定义；我实现的是运动学 TTC（间距 ÷ 闭合速度）。请确认。另外 `separation_kind = surrogate` 时 TTC 是到原点重合的时间，会偏大。
10. **`semantics.yaml` 的 `contact.impulse_gate_ns` 现在没有任何代码使用。** 00 §11 的预注册清单里列了“冲量门槛”，但 dynamic_release 方案不需要。建议删除，或说明它在哪里起作用。
11. **（范围之外，只记录）T01 的 `test_source_hygiene.py` 在 Python 3.8 下用一个固定的标准库白名单**（`dataclasses enum functools hashlib json math numbers os pathlib re typing __future__`），而 3.10+ 用 `sys.stdlib_module_names`。T04–T06 若 import `collections`、`itertools`、`copy`、`bisect`、`abc`、`io` 等，会**只在 `hz38` 上**让卫生测试失败。T03 的新模块刻意只用了白名单内的模块。建议把白名单扩成一个明确的超集，或让后续任务知道这一点。
