## 偏离设计文档之处与理由

1. **`Path` 是基类加解析子类，而不是单一的“时间戳 + 位置”采样类。** 任务文件写“统一的 `Path`（时间戳 + 位置 [+ 姿态]）”。用采样表示任意路径无法同时满足“命中点误差 < 1e-6 m”，所以 `LinePath`（直线 + 时间剖面 + 抛物线抬升）与 `BallisticPath` 是解析的，`SampledPath` 用于探针给出的名义 EEF 路径。三者共用 `pos / vel / quat / sample / finite_difference_velocity`。
2. **`estimate_t_stop` 比任务文件多两个必填参数**：`k`（任务文件说“k 为参数”）与 `t_hold_s`（保持动作发出的时刻）。我不愿隐含“第一个样本就是保持起点”，所以显式传入，早于它的样本被忽略。
3. **`aggregate_t_stop` 返回 `TStopSummary`，不是只有 (中位数, IQR)。** 它还带 `n_total / n_valid / n_censored` 与四分位数。未停下的重复记为 `None`，被排除出统计并计数，所以有删失时中位数偏乐观，调用方必须看 `n_censored`。
4. **`min_jerk` 的一条参照测试容差由我首版的 1e-15 放宽为 1e-14。** 首版在 `test_min_jerk_matches_the_closed_form_and_is_symmetric_and_monotone` 里用了 1e-15，实际失败（最大差 3.2e-15）。原因是该多项式的各项（10、15、6）相消到 ≤ 1，两个代数等价写法的舍入差量级就是 (10+15+6)·ε ≈ 7e-15。这是我自己新写的测试而非任务文件给定的标准，实现本身没有改。依据已写进该测试的注释。
5. **fall 族在 onset 零速释放，由引擎重力接管**（`release_time_s = onset`，`release_velocity = 0`），而 slide / reach 族是运动学推进到 `t_hit` 再以有限差分速度释放。理由：任务文件写“从静止释放”；这样 fall 的落地时刻由引擎重力决定，需要 `g` 作为参数（调用方传引擎自己的值）。T04 若想改成“运动学下落到 `t_hit`”，需要把 `release_time_s` 改为 `t_hit`，同时把 `release_velocity` 改为 `hit_velocity`（`(0, 0, -g τ)`）；路径本身已覆盖 `[onset, t_hit]`。

## 各族“名义必碰”的参数化假设（给 T06 对接）

通用约定（`kinematics/hit.py` 模块文档字符串有完整版）：

- **`hit_point` 是危险体质心在 `t_hit` 的目标位置**。曝光偏移（`HazardSpec.exposure.offset_m`）与接触余量（危险体半径 + 夹爪半径）由调用方在调用前加上，这里不加。因此首次物理接触比 `t_hit` 早约 `(半径之和) / 逼近速度`。
- `nominal_ee_path` 只用于检查 `t_hit` 在其时间范围内并给出诊断，不会移动命中点。`diagnostics["nominal_ee_offset_m"]` 是 `hit_point` 与名义路径在 `t_hit` 实际位置的距离（调用方传路径上的点则为 0）。
- `onset_time_s = t_hit − τ` 恒成立，也是返回路径的起点。若 onset 早于名义路径起点，**不抛错**，而是在 `diagnostics["onset_margin_s"]` 里给出负值，由 G0 判定。
- 方向向量在内部归一化；任何参数缺失或多余都抛 `ValueError`。

| 族 | `params`（全部必填） | 几何与时间 | 释放 |
|---|---|---|---|
| `intrusion.fall` | `g` | 释放点 = `hit_point + (0, 0, g τ²/2)`；从静止自由下落，`t_hit` 时质心恰在 `hit_point`；命中速度 `g τ` 向下 | `release_time_s = onset`，速度 0 |
| `intrusion.slide` | `direction`、`speed_mps`、`hook_dt_s` | 起点 = `hit_point − direction·speed·τ`，onset 在起点，匀速到 `hit_point`；`direction` 不强制水平 | `release_time_s = t_hit`，速度 = 最后一个钩子步的后向有限差分（约 `speed·direction`） |
| `intrusion.reach` | `direction`、`reach_distance_m`、`overshoot_m`、`speed_profile`、`hook_dt_s` | 起点 = `hit_point − direction·reach_distance_m`（onset 时），终点 = `hit_point + direction·overshoot_m`；总时长由“在 `t_hit` 恰经过 `hit_point`”反解（`u_hit = s⁻¹(L_hit/L)`，`T = τ/u_hit`）；`speed_profile ∈ {min_jerk, linear}`；路径可延伸到 `t_hit` 之后 | 同 slide |

`HitPlan` 还给出 `hit_velocity`（解析 `path.vel(t_hit)`）与 `diagnostics`：`nominal_ee_offset_m`、`onset_margin_s`、`travel_distance_m`、`hit_speed_mps`、`relative_speed_at_hit_mps`（相对名义 EEF 速度）。`release_velocity` 只含线速度，角速度由调用方填 0。

## 对设计文档的修订建议（只提议，不改文件）

1. **00 §5.1 / §5.2 的 `t_hit` 定义与构造不一致。** §5.1 说 `t_hit` 是“名义 EEF 与危险体首次接触的时刻”，§5.2 与 T02 构造的是“质心重合”。建议明确：τ 以质心重合时刻定义，并把接触余量（半径之和）作为调用方的显式输入；或者改定义为首次表面接触，由 T06 传入已减去余量的 `hit_point`。我按前者实现并写进了文档字符串。
2. **R7 与 T02 的释放速度**：`release_velocity` 依赖 `hook_dt_s`（见上文 `overshoot_m = 0` 的数字）。建议 01 的 R7 写明“钩子步长必须随实例一并记录”，否则同一实例在不同引擎上会得到不同的释放速度。
3. **fall 族的释放方式**需要在 00 §5.2 或 T04 的任务文件里定下来：在 onset 零速释放（我的实现），还是运动学下落到 `t_hit` 再释放。两者给出的落地时刻与速度在理想情况下相同，但前者依赖引擎重力，后者不依赖。
4. **`configs/hazard/intensity.yaml` 缺 T02 需要预注册的键**：`calibration` 下已有 `t_stop_speed_threshold_mps`，但没有 `estimate_t_stop` 的 `k`（建议 `t_stop_min_consecutive_samples`），也没有阶梯法的 `step_s / tau_min_s / tau_max_s`，以及 R1 的 `max_step_m` 与最小半尺寸的比例（01 R1 的 0.5）。这些现在由调用方传入，没有 YAML 来源。T01 的骨架文件我没动，按铁律 2 的精神留给你决定。
5. **00 §4 的 `intrusion.slide` 强度轴“预兆提前量”**：请定义它是否计入 τ（即 onset 是预兆开始还是物体开始运动），T06 才能无歧义实现。
