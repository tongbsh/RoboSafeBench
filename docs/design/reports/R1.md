## 做了什么

- **`driving.py`（唯一一处）**：`EpisodeSession.run_episode` 增加可选关键字 `task_entities`、`control_onset_s`，原样传给 `runtime.arm`。默认值让既有调用方行为不变。为什么还加了 `task_entities`，见“偏离”第 1 条。
- **新包 `hazardlib/src/hazardlib/run/`**（只依赖 numpy、pyyaml 与 hazardlib 自身，Python 3.8 语法）：
  - `settings.py`：`RunSettings.load(config_dir)` 以 `strict=True` 读 `run.yaml`，一次报出所有缺失或 `PLACEHOLDER` 的键；校验取值；`config_hash = sha256_hex(解析后的 run.yaml)`，与 `Manifest.config_hashes` 同一算法。
  - `inputs.py`：正式模式 `load_formal`（先 `verify_manifest(manifest_dir, config_dir, bd)`，不过即拒绝）与试点模式 `load_pilot`。两者都拒绝无证书的实例、重复 id、TaskContext 哈希或 BD 哈希不符的实例。
  - `plan.py`：回合计划。每个实例 × 每个种子一个危险回合，配一个对照回合（同任务、布局、种子；`control_onset_s` = 实例名义 onset；回合长度同实例）。名义 onset 与回合长度都相同的实例共用一个对照回合，只跑一次。
  - `runner.py`：`run_stage(...)`。做 §5.4 检查与 BD 一致性检查；有删失的 T_stop 默认拒绝（D8）。每回合补 `exposure_low`（`annotate_exposure`），Σ 经 `sigma_from_summary` 计算，记录逐条追加并 `fsync`。按（回合 id，策略名，种子）续跑；输出目录的身份不符时拒绝。
  - `frames.py`：`FrameRecorder`（包装被测策略，把 `act` 收到的指定键图像连同仿真时间、危险体阶段交给 `FrameSink`）、`FrameSink` 协议、`MemoryFrameSink`（测试用）、`NpyFrameSink`（只用 numpy 写 `.npy` + `frames.json`）、`TimedPolicy`（每步推理墙钟时间，只作诊断）。
  - `report.py`：`hazardctl report` 的汇总。主表（`certified` / `uncertified†` 行）按策略 × 族 × τ 分档，有校准时另出 Σ 分档；单列桶为 `unsolvable_by_probes`、`baseline_unusable`、`invalid`、`exposure_low`；另有对照回合表和 `engine_peak_force_n` 附表。拒绝混合试点与正式结果，也拒绝混合不同 Manifest、BD、校准或回合设置的结果，以及重复回合。
  - `stats.py`：Clopper–Pearson（二项尾概率二分求根，`math.lgamma`）与 Wilson 区间、四分位数，都不依赖 scipy。
- **`cli.py`**：只加了 `run`、`report` 两个子命令（以及模块文档和 parser 描述里对应的说明）。
- **`configs/hazard/run.yaml`**：6 个键，全部 `PLACEHOLDER`。
- **测试 `hazardlib/tests/run/`**（只增加，46 个）：`run_world.py`（FakeHost 世界与脚本策略）、`test_run_settings.py`、`test_run_stats.py`、`test_run_plan.py`、`test_run_frames.py`、`test_run_stage.py`、`test_run_report.py`、`test_run_cli.py`（端到端）。

```
hazardctl --config-dir configs/hazard/pilot/<bench> run ... --instances gated.jsonl --task-context ... --bd bd.yaml \
    [--calibration calibration.yaml] --pilot
# 汇总（一个或多个 run 目录）
hazardctl --config-dir CFG report --runs runs/A runs/B --out-dir report
```

- 策略工厂按 `F(host, **policy_args)` 构造；帧接收器按 `F(frames_dir, **frame_sink_args)` 构造，`frames_dir = <out-dir>/frames`。
- 拒绝时退出码为 2，所有问题一并列出，与既有子命令一致。
- `--seeds`：每个实例在每个种子下各跑一次（对照回合同种子）。
- `--labels`：缺省时跑全部标签。`unsolvable_by_probes`、`baseline_unusable` 照常运行，汇总时只进单列桶。

**`<out-dir>/episodes.jsonl`**：每回合一行（`record_version: "1"`），逐条追加并 `fsync`。

| 字段 | 含义 |
|---|---|
| `kind` | `hazard` / `control` |
| `episode_id` | 危险回合 = 实例 id；对照回合 = `control_id` |

| `label`、`in_main_score` | 证书标签与 `gates.in_main_score` |

## `run.yaml` 键表

| 键 | 含义 | 使用者 |
|---|---|---|
| `episode.horizon_extra_s` | 回合长度 = max(TaskContext 名义成功时刻, 实例 `nominal_hit_time_s`) + 本值，与 G1 回合同一规则（00 §8）；对照回合用配对实例的长度 | `run` |
| `episode.stop_on_success` | `true`：在第一个成功的控制步结束回合（基准原生评测循环多如此），此后的接触观测不到；`false`：跑满 | `run` |
| `report.tau_bin_edges_s` | τ 分档的递增边界（秒）；档为 `[e_k, e_k+1)`，两端是开放档 `<e_0`、`>=e_last`，不丢值 | `report` |
| `report.sigma_bin_edges` | Σ = τ / T_stop 的分档边界，规则同上（只在有校准时用） | `report` |
| `report.interval.method` | 比例的区间估计：`clopper_pearson`（精确）或 `wilson`（score） | `report` |
| `report.interval.confidence` | 双侧置信水平，取值在 (0, 1) | `report` |

区间方法的建议：取 `clopper_pearson`、0.95。理由如下。每档样本量小（每档几十个回合）；接触率、倾倒率常在 0 或 1 附近，0/n、n/n 很常见。Clopper–Pearson 在任何 p 下覆盖率都不低于名义值，代价是偏保守。Wilson 的平均覆盖率接近名义值，但在 p 接近 0 或 1 且 n 小的时候会低于名义值。主张的是“策略 A 的接触率不高于 B”这类结论，保守一侧更稳妥。这只是建议，值仍是 PLACEHOLDER。

## 偏离设计文档之处与理由

1. **`driving.py` 透传了两个参数，不只 `control_onset_s`。** 原来的 `run_episode` 根本不传 `task_entities`。运行时没有 `task_entities` 就不监测倾倒（`runtime.py` 模块文档：“`task_entities=None` leaves both `None`”），只透传 `control_onset_s` 时 `toppled` 永远是 `None`，净值无从谈起。两个参数都是可选关键字、原样透传，既有调用方不受影响。改动仍只在 `run_episode` 这一处，没有碰 trace 部分；与 T07 的试合并自动通过。
2. **冻结目录里没有 TaskContext 和 BD**（`write_frozen` 不复制它们），而 prompt 要求从冻结目录读，我又不能改 freeze。所以正式模式用 `--task-context`、`--bd` 传入，再对冻结状态逐一核对：
   - BD：`verify_manifest(..., bd=...)` 比对 `bd_hash`；
   - 每个 TaskContext：比对实例 `provenance.task_context_hash`；
   - TaskContext 集合：重算 Manifest 的 `probe_set_hash` 并比对；
   - 宿主：`host.describe()` 的哈希必须等于输入 BD 的哈希。
   实例与校准仍从冻结目录读。
3. **`uncertified` 进主表，但单独成行。** `in_main_score` 只对 `wait_solvable` / `evade_solvable` 为真，prompt 又要求“`uncertified` 进主表并加脚注”。我的做法：主表每行带证书类别列，`certified` 行就是 `in_main_score` 的回合，`uncertified†` 行另起并加脚注，两者不合并进同一个比例。记录里的 `in_main_score` 原样保存。
4. **“成功”取 `success_t_s` 非空**，即任一控制步上 `task_success` 为真，与门控同一口径，也与基准原生“首次成功即完成”一致。`log.task_success`（回合结束时的读数）照样记录。两者只在 `stop_on_success: false` 且成功后又失败时才不同。
5. **对照回合的去重键是（任务，布局，种子，名义 onset，回合长度）。** D12 a 要求对照的倾倒参考时刻等于配对实例的名义 onset，onset 不同的实例不能共用同一个对照。所以“同布局共用”只在 onset 与长度都相同时发生（FakeHost 端到端里 `fall_wait` 与 `fall_long` 就是这样）。`control_id = "control:" + 共用实例中最小的 id`，取自本次 `--labels` 选中的实例；同一目录用不同 `--labels` 续跑时，id 可能变化而多跑一个对照（不影响汇总的配对，因为配对按危险记录里的 `control_id`）。
6. **新增 `--no-topple`。** TaskContext 的实体里可能有不在 `object_poses` 里的名字（例如静态声明的目标区域、宿主不作为物体报告的抓持物），这时运行时在 `begin_episode` 里会拒绝。`--no-topple` 关掉倾倒监测，`toppled` 记 `null`，报告里倾倒列显示 n/a；这个开关进入续跑身份。
7. **T_stop 删失时默认拒绝运行，`--allow-censored-t-stop` 才放行**（D8 的默认拒绝）。放行后记录与汇总都标 `sigma_is_upper_bound`。
8. **种子用 `--seeds S ...` 列表**，没有用“起点 + 个数”的写法，续跑加种子更直接。
9. **`report` 拒绝混合的范围比 prompt 宽。** 除了试点 / 正式与 `manifest_hash`，BD 哈希、校准哈希、回合设置不同的目录也拒绝合并（试点模式下这些没有 Manifest 保证一致），重复回合同样拒绝。
10. **τ 取 `nominal_hit_time_s − onset_time_s`**（00 §5.1 的定义），不取 `provenance.tau_s`（规格强度）。对实例化器产生的实例两者相等。

## 对设计文档的修订建议（只提议，不改文件）

1. **`run.yaml` 是否进入 `freeze` 的 `config_hashes`（需协调者定）。** `run.yaml` 的 `episode` 段（回合长度、成功即停）决定正式结果怎么测，应当随版本冻结；`report` 段（分档、区间）只影响呈现，汇总时可以改。建议二选一：
   - (a) 拆成 `run.yaml`（`episode` 段，进 `USED_CONFIGS` 与 Manifest，`verify` 校验）和 `report.yaml`（不冻结，`summary.yaml` 记它的哈希）；
   - (b) 整个 `run.yaml` 进 `config_hashes`，接受改分档也要重新冻结。
   我倾向 (a)。在定下来之前，每条记录、`run_meta.yaml` 和 `summary.yaml` 都已记了 `run_config_hash`。
2. **`write_frozen` 复制所用的 TaskContext 和 BD**，Manifest 增加 TaskContext 哈希列表。这样正式模式只需 `--manifest-dir`，不必在命令行传入再核对（偏离 2）。
3. **D12 a / D10 h 补一句：** 对照回合与实例一一对应参考时刻，因此对照只能在 onset 相同的实例间共用（偏离 5）。
4. **00 §8 与 `gates/decision.py` 文档对 `uncertified` 的位置写法不一**（“主表脚注”与“单独报告”）。建议明确为“主表内单独成行加脚注、不并入 `in_main_score` 的比例”（偏离 3）。
5. **00 §6 写明“成功”的口径**：任一步成功，还是回合结束时成功（偏离 4）。
