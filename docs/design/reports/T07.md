推导（`kinematics/standoff.py` 模块文档字符串、`sphere_sampling_error_bound`）：采样点都在真实表面上，所以 s* 只会偏小。若真实接触点与最近采样点的弦长为 δ（对应圆心角 θ，δ = 2 r_e sin(θ/2)），则误差 = r + r_e − r_e cos θ − sqrt(r² − r_e² sin²θ) ≈ (δ²/2)(1/r_e + 1/r)。FakeHost 的采样保证任一表面点到某采样点不超过一个间距 g，取 δ = g 得到上表的界；实测最大误差都在界内，约为界的 40–45%（g ≤ 0.01）。prompt 写的球对球 `r − sqrt(r² − (g/2)²)` 量级 ≈ g²/(8r) 是“接触点正好落在两采样点中间、只算危险体一侧”的情形；把机器人球面曲率也算上并取最坏的 δ = g 就是上面的式子，两者同为 O(g²)。

C13 在默认世界里对间距不敏感：三族的接近方向都是坐标轴方向，而 FakeHost 的采样包含两极与 ±x、±y 方向的点，所以 s* 恰为 0.05 m。

## 偏离设计文档之处与理由

1. **`robot_point_spacing_m: unknown` 是声明，不是待测项。** 01 §2 与 D15 a 写“`unknown` 表示不提供几何”。若按 BD 的一般规则把它当未完成的 probe，`strict=True`（正式实验）下所有不提供几何的宿主（目前的 CALVIN）都无法加载。因此在 `spec/benchmark_descriptor.py` 加 `DECLARATIVE_UNKNOWN_FIELDS = ("robot_point_spacing_m",)`：`unknown_fields()` 不列它，`strict` 接受它；其他 `unknown` / PLACEHOLDER 照旧拒绝。为此对 `hazardlib/config.py` 的 `load_bd(strict=True)` 做了最小修改（`_check_strict` 增 `declarative` 参数）——`config.py` 不在 prompt 列出的可改文件里，请协调者追认。
2. **slide 括号失败沿用 `no_support_surface`**，与标量分支同一原因（“EEF 离支撑面太高、碰不到”）；只有二分收敛到几何 standoff 跳变处才用新原因 `slide_normal_unsolved`。另一选择是括号失败也用新原因，但那会让同一物理情形在有无几何时报不同原因。
3. **instance 与 TaskContext 的哈希会变**（无几何时数值仍逐位相同）：实例 `provenance` 新增 3 个键；由 `build_task_context` 生成的 TaskContext 的 `provenance` 新增键、trace schema 升到 2，旧 trace 要重录。逐位相同由 `test_without_geometry_builder_and_g0_are_bit_identical_to_the_integration_branch` 钉定（8 个规格的全部关键帧、时间、释放、standoff 数字与 G0 检查，以 float hex 计算 SHA-256；摘要用 `6449277` 的代码在 hz38 与 hz311 上算出且一致）。
4. FakeHost 的 `collision_body_quat` 恒为单位四元数（FakeHost 刚体是球，朝向不影响几何）；非单位朝向的插值与旋转由 `test_standoff.py` 的单元测试与 `test_pipeline_geometry.py` 的手写 trace 覆盖，FakeHost 上没有端到端地覆盖到旋转刚体。
